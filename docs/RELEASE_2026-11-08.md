El servidor se publicó en Workers Free y la base D1 está preparada. La [comprobación desde una red independiente](https://github.com/rommer1997/CANTERA-/actions/runs/42494911375) obtiene la configuración correcta (`ready:true`), sin solicitar identidad ni datos privados.

Desde la conexión de trabajo, ambas IP que devuelve el DNS del endpoint agotan la conexión TCP. El responsable también confirma el error del servidor en iPhone, con Wi-Fi y con datos móviles. No se atribuye la causa a un operador o bloqueo concreto sin pruebas suficientes. Esa comprobación corresponde al endpoint inicial. No hay recepción push física confirmada.

Se preparó una entrada HTTP equivalente en Cloudflare Pages Functions, con la misma base D1, claves VAPID y permisos de Firebase. El Worker original conservaría los reintentos programados. La app permanecería alojada en Firebase. El paquete se compiló y comprobó en Miniflare local; el [commit de preparación](https://github.com/rommer1997/CANTERA-/commit/94839aa2eedd4b70648ee46b4b396d8d23ed9709) pasó su [CI](https://github.com/rommer1997/CANTERA-/actions/runs/42496526962).

Esta dirección se comprobó desde la conexión afectada: 200/ready:true, 401 sin sesión y 403 desde origen ajeno. Se publicó y verificó el build conectado a Pages. En la web real desapareció el error y se comprobó que «Activar notificaciones» está habilitado. La comprobación del iPhone se ha solicitado de nuevo y sigue pendiente. No se han cambiado planes, facturación, DNS ni roles administrativos; la recepción física continúa pendiente.
